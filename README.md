A CamScanner-style document scanner for the web. Turn phone photos and PDFs
into clean, flat, high-contrast scans with uniform A4 pages — on the server, or
fully on-device in the browser.

**Live demo:** [camscannerclone.vercel.app](https://camscannerclone.vercel.app) ·

## Overview

RScan has two scan paths that share one algorithm:

| Path | Where it runs | Best for |
|---|---|---|
| **Server scan** | Flask + OpenCV + PyMuPDF | image batches and small/medium PDFs, local runs |
| **On-device scan** (`/scan-pdf`) | pdf.js + OpenCV.js (WASM) + pdf-lib | any-size PDFs, privacy, serverless limits |

The Python and JavaScript implementations are kept numerically aligned by a
parity suite that compares the browser output against fixtures generated by the
Python pipeline (`bun run parity`).

## Features

* **Document geometry** — 4-point perspective warp when a page border exists;
  ruling-line dewarp and keystone correction for curved notebook pages; colored
  ruling fallback (pink/red margins) for tilt that luminance cannot see.
* **Photometry** — illumination flattening, white-point stretch to pure white,
  double black-point stretch for deep ink, chroma-preserving saturation boost,
  light unsharp masking.
* **Cleanup** — page-gap shadow trim, warp-fill trim, spiral binding removal
  (thickness + diagonal signature), corner-smear and border-artifact whitening.
* **Reference-quality framing** — pages are re-framed with symmetric margins to
  a consistent canvas aspect ratio.
* **Uniform A4 output** — every PDF page is A4 (orientation matched to the
  image, full-bleed) with a thin black frame.
* **Live progress** — server PDF scans stream `loading → detected → scanning →
  page_done → assembling → done` over SSE; the on-device path shows the same
  step log locally.
* **Page-limit picker** — 10/20/30/40/50/All on both scan pages (local caps:
  250 MB, 250 pages).
* **Parallel page scanning** — server PDF jobs scan pages on a bounded CPU
  pool, and local scans run a worker pool (one OpenCV.js worker per page, up to
  4 pages at once) with out-of-order-free, in-order assembly.
* **EXIF-aware uploads** — phone photos are rotated upright before scanning.
* **No accounts, no database, no API keys** — files stay on the machine or in
  the browser.

## Quickstart

Prerequisites: Python 3.9+ and pip. Bun is only needed to rebuild vendored
frontend artifacts (the built files are committed).

```bash
git clone https://github.com/minhazexo/cam-clone.git
cd cam-clone

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # headless OpenCV: no libGL required

python app.py                      # → http://localhost:5000
```

Open `/` for images and server PDF scans, or `/scan-pdf` for the on-device
flow. To rebuild the vendored runtime:

```bash
bun install
bun run build                      # static/vendor/runtime.js + pdf.worker.js
```

## How scanning works

1. **Detect geometry** — find the page quad, or use ruling lines to dewarp a
   curved page, or fall back to a rotation deskew.
2. **Trim edges** — remove warp fill, trailing shadows and smeared bands while
   they are still dark (before enhancement).
3. **Enhance** — flatten illumination, stretch highlights to white, deepen ink
   twice, keep colored ink saturated.
4. **Clean and re-frame** — inpaint spiral binding, straighten the residual
   curl, whiten corner/border artifacts, re-frame with reference margins.
5. **Sharpen and size** — light unsharp, then fit to the reference canvas.

Stage-by-stage detail, constants and the worker protocol:
[`docs/SCAN_PIPELINE.md`](docs/SCAN_PIPELINE.md).

### Image scanning

`POST /api/scan` with `files[]`; the server decodes (EXIF aware), scans each
image, stores `<id>.jpg` and returns `{"pages":[{name,id,width,height}]}`.
Duplicates are collapsed, unsupported files are skipped, and a per-file failure
becomes an `error` entry rather than losing the batch.

### PDF scanning (server)

Drop a PDF on `/`: `POST /api/scan-pdf-start` creates a job, pages are rendered
at 200 DPI and scanned in parallel, progress streams over SSE, and the assembled
PDF is downloaded from `/api/pdf/<name>`. `POST /api/scan-pdf` is the
synchronous variant used for small files and scripts.

### On-device scanning

`/scan-pdf` renders pages with pdf.js, enhances them in an OpenCV.js worker and
assembles A4 pages with pdf-lib. Nothing is uploaded, so document size is
limited only by browser memory (250 MB / 250 pages locally).

Pipeline details: [`docs/PDF_PIPELINE.md`](docs/PDF_PIPELINE.md).

## API

| Endpoint | Method | Description |
|---|---|---|
| `/api/health` | GET | `{"status":"ok","service":"rscan"}` |
| `/api/scan` | POST | scan images → `{"pages":[…]}`
| `/api/scan-pdf` | POST | scan a PDF synchronously → `{"pdf":"scanned_…pdf"}` |
| `/api/scan-pdf-start` | POST | start a background job → `{"job_id":"…"}` |
| `/api/scan-pdf-progress/<job_id>` | GET (SSE) | progress events per page |
| `/api/image/<id>` | GET | download a scanned image |
| `/api/pdf/<filename>` | GET | download a scanned PDF |

Example:

```bash
curl -F "files=@photo.jpg" http://localhost:5000/api/scan
curl http://localhost:5000/api/health
```

Full request/response/error contract: [`docs/API.md`](docs/API.md).

## Development

```bash
bun install                # tooling only (vendoring + tests)
bun run build              # rebuild static/vendor artifacts
bun run parity             # scanner parity harnesses
bun run test               # full suite: assets, parity, JS, Python
python app.py              # dev server
```

```bash
python RScan/Python/scan/scan_pdf.py input.pdf output.pdf --dpi 200 --jpeg-quality 78
```

Reference-anchored quality gate (needs the local reference assets):

```bash
python scripts/quality_gate.py
```

### Parity verification

```bash
bun run parity
# tilt_ruled: MAD=0.049 (gate <=3.0) dims=790x1117 …
# tilt_plain: MAD=0.042 (gate <=3.0) dims=791x1119 …
```

Fixtures in `tests/fixtures/` are produced by the Python pipeline; the harnesses
compare the JavaScript/WASM output against them with an explicit tolerance. A
failing gate means the two implementations drifted — investigate, do not raise
the threshold.

## Deployment

**Local:** `python app.py` (port `PORT`, default 5000) — 50 MB uploads,
unlimited scan time.

**Vercel:** import the repository; `vercel.json` routes everything to
`api/index.py`. No build command, no environment variables required. Verify
`/api/health` after deploying.

| Concern | Local | Vercel Hobby |
|---|---|---|
| Request body | 50 MB | ~4.5 MB |
| Function time | unlimited | ~60 s |
| Disk | your machine | ephemeral `/tmp` |
| Large PDFs | server or on-device | use `/scan-pdf` (on-device) |

Details and operational notes: [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

## Security and privacy

* No accounts, no database, no third-party services, no API keys.
* Local runs write artifacts under the system temp directory and remove
  transient inputs after each scan.
* The on-device path never uploads anything; the file stays in the browser.
* Uploads are validated by extension and decoded defensively; artifact names
  are sanitised so a crafted URL cannot escape the storage root.
* Error responses never contain stack traces; full detail goes to the server log.

Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md).
